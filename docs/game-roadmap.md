# نقشه راه ۱۰۰ بازی مستقل — فاز D

تاریخ: ۲۰۲۶-۱۰-۱۹ — شاخه: `arena/eedcea27-kartoniya` — HEAD: `5c33cf4` (گزارش قبلی `e2c0ceb` اصلاح شد)

این سند طراحی ۱۰۰ بازی را با ۱۰ ویژگی الزامی مستند می‌کند. از ۱۶ موتور موجود به‌عنوان زیرساخت استفاده می‌شود، اما «موتور مشترک ≠ بازی مستقل» رعایت شده — هر عنوان تجربه، قوانین یا مراحل متفاوت دارد. اگر دو عنوان فقط در رنگ/نام تفاوت داشته باشند، به‌عنوان یک خانواده حساب شده و برای یکی مکانیک جایگزین پیشنهاد شده است.

## موتورهای موجود (۱۶)
- Memory (memory_match/sequence/position) — کارت برگردان، توالی، موقعیت
- SlidePuzzle (slide/jigsaw/rotate/block/tangram) — لغزش کاشی (اکنون solvable)
- Coloring (coloring/color_by_number) — ۴×۴ انتخاب رنگ
- Difference/Hidden (spot_difference/hidden_objects) — ۵ نقطه
- ShadowMatch (shadow/shape/mirror) — انتخاب و تطبیق سایه
- Counting (counting/addition/subtraction/number_sort/compare/even_odd/number_hunt)
- Reaction (tap_green/catch/whack/balloon/traffic/quick/avoid)
- Maze (maze/maze_collect) — ۵×۵ با دیوار
- OddOneOut (odd_one_out/find_one/color_tap)
- Sorting (size_sort/color_sort/sorting)
- Pattern (pattern_complete/logic_pick/logic_grid/pattern_follow)
- Guess (guess_blur/silhouette/partial/sound/emoji)
- Word (word_build/missing_letter/letter_pick/letter_hunt/word_search/tracing/rhyme)
- Riddle (riddle_pick/mixed_challenge)
- MathRace (math_race) — تایمر ۸ثانیه
- GameScaffold — هدر مشترک

## اصول تفکیک استقلال
1. تغییر رنگ/نام/تصویر به‌تنهایی کافی نیست — باید هدف متفاوت یا شرط برد متفاوت باشد.
2. reuse موتور مجاز است اگر تعامل متفاوت باشد (مثلاً Memory ۲×۲ خردسال vs ۴×۳ توالی).
3. هر گروه ۵تایی باید تنوع سنی ۳-۱۰ و دسته‌بندی متفاوت پوشش دهد.
4. تست‌ها برای هر بازی: منطق امتیاز، پایان، restart، dispose تایمر.

## فاز D — ۵ بازی جدید برای تنوع (گروه اول)

این ۵ بازی بیشترین تمایز را نسبت به ۱۶ موتور موجود ایجاد می‌کنند و هر کدام موتور جدید می‌طلبد:

### D1. `story_order` — مرتب‌سازی مراحل داستان
- دسته: riddle/sorting | هدف: ۴ تصویر داستان (کاشت → آبیاری → رشد → برداشت) را به ترتیب بکش
- قوانین: ۴ کارت قابل جابجایی با ReorderableListView، فقط یک ترتیب صحیح
- تعامل: drag-and-drop عمودی، دکمه بررسی
- برد: ترتیب صحیح → +۱۰، ۵ مرحله با داستان‌های متفاوت (صبحانه، سفر، کاشت)
- امتیاز: ۵۰ حداکثر، ذخیره بهترین
- تفاوت: تنها بازی روایت ترتیبی (story sequencing) — موتور StoryOrder جدید
- تست: ترتیب صحیح/غلط، امتیاز، restart، dispose

### D2. `jigsaw_drag` — جورچین ۲×۲ کشیدنی
- دسته: puzzle | هدف: ۴ تکه پازل را به جای صحیح بکش
- قوانین: ۴ قطعه با Target، Draggable با feedback، جای‌گذاری صحیح قفل می‌شود
- تعامل: drag-and-drop به Grid ۲×۲
- برد: هر ۴ تکه درست → پایان، +۱۰ هر تکه
- امتیاز: ۴۰ حداکثر
- تفاوت: تنها جورچین واقعی با drag (نه slide) — موتور JigsawDrag جدید
- تست: drop صحیح/غلط، قفل، restart

### D3. `color_pattern_builder` — ساخت الگو رنگی
- دسته: sorting/pattern | هدف: الگوی «قرمز-آبی-قرمز» را با افزودن رنگ بساز
- قوانین: نمایش توالی ناقص، انتخاب از پالت ۴ رنگ برای تکمیل ۳ خانه خالی
- تعامل: tap پالت → پر کردن خانه، قابلیت پاک کردن
- برد: تکمیل صحیح ۵ الگو
- امتیاز: ۵۰
- تفاوت: ساخت الگو (builder) vs تشخیص الگو (pattern_complete) — موتور ColorPattern جدید
- تست: الگوی صحیح/غلط، امتیاز، timer cleanup

### D4. `number_quantity` — تطبیق عدد با تعداد
- دسته: numbers | هدف: عدد ۵ را به ۵ سیب وصل کن
- قوانین: ۴ عدد و ۴ گروه اشیا (🍎×3, ⭐×5...)، انتخاب عدد سپس گروه
- تعامل: tap عدد → tap گروه
- برد: هر ۴ جفت صحیح
- امتیاز: ۴۰
- تفاوت: تطبیق کمّی (number ↔ quantity) vs شمارش ساده — موتور QuantityMatch جدید
- تست: جفت صحیح/غلط، حذف جفت شده، پایان

### D5. `habitat_sort` — دسته‌بندی زیستگاه
- دسته: sorting/animals | هدف: حیوان را به خانه‌اش ببر (جنگل/دریا/مزرعه)
- قوانین: ۶ حیوان، ۳ سبد زیستگاه، drag هر حیوان به سبد صحیح
- تعامل: Draggable حیوان → DragTarget سبد
- برد: هر ۶ صحیح با بازخورد فوری
- امتیاز: ۶۰
- تفاوت: دسته‌بندی چندمعیاره (habitat) vs مرتب‌سازی ساده — موتور HabitatSort جدید
- تست: drop صحیح/غلط، شمارش، restart

> پس از این ۵، مستقل‌ها از ۱۶ به ۲۱ می‌رسد. فازهای بعدی ۵تایی ادامه می‌یابد تا ۱۰۰.

# اولویت‌بندی ۷۹ پوسته باقی‌مانده — فاز E

از ۱۰۰ عنوان، ۲۱ موتور مستقل است (۱۶ اولیه + ۵ جدید فاز D). ۷۹ عنوان دیگر پوسته‌هایی از همین موتورهاست که طبق معیار «رنگ/نام کافی نیست» مستقل محسوب نمی‌شوند. برای رسیدن به ۱۰۰ مستقل، هر پوسته باید با مکانیک جدید جایگزین شود.

## اولویت ۱ — ۱۵ عنوان (دسته‌های کم‌پوشش + toddler)
`memory_sounds`→`story_order` (riddle) ✅، `puzzle_picture_logic`→`jigsaw_drag` (puzzle) ✅، `puzzle_color_seq`→`color_pattern` (sorting) ✅، `hidden_garden`→`habitat_sort` (sorting) ✅، `sorting_fruits_veg`→`number_quantity` (numbers) ✅ — ۵ انجام شد، ۱۰ مانده:
`memory_animals`, `coloring_number`, `difference_light`, `hidden_objects2`, `shadow_match2`, `counting_5`, `reaction_tap_green2`, `maze_simple`, `odd_one_shape`, `sorting_size` → هرکدام نیاز به موتور جدید (مثلاً memory با صدا، coloring با الگو، difference با زمان، maze با جمع‌آوری)

## اولویت ۲ — ۲۵ عنوان (تکمیل ۱۵ دسته به ۶-۷ عنوان)
هر دسته باید ۶-۷ بازی داشته باشد تا تنوع تضمین شود. دسته‌های فعلی: puzzle ۷، memory ۷، sorting ۶، etc. دسته‌های کم: toddler (۳)، shape-match (۲)، maze (۴) — ۲۵ عنوان بعدی باید این خلأ را پر کند با موتورهای جدید: shape-rotation, toddler-tap, maze-collect

## اولویت ۳ — ۳۹ عنوان (گسترش عمقی)
باقی‌مانده برای رسیدن به ۱۰۰، با تمرکز بر مکانیک‌های سخت (riddle/hard, reaction/hard) و ترکیبی (mixed_challenge) — هرکدام باید تست `flutter test` + `small_screen 320px` + `mounted` را بدون overflow بگذراند.

## معیار تبدیل پوسته به مستقل
- ورودی متفاوت (tap vs drag vs swipe vs reorder)
- شرط برد متفاوت (زمان vs امتیاز vs تعداد مرحله)
- UI متفاوت (grid 3×3 vs 4×4 vs list vs canvas)
- تست مستقل (file: `test/game_logic_test.dart` + widgetTest برای هر موتور)
