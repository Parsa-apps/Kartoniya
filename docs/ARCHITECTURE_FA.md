# تصمیمات معماری کارتونیا

## اطلاعات پروژهٔ استخراج‌شده

| مورد | تصمیم فعلی |
|---|---|
| نام و موضوع | کارتونیا؛ کاتالوگ و پخش انیمیشن/کارتون کودک |
| مخاطب | کودکان همراه والدین فارسی‌زبان؛ انتشار Android در کافه‌بازار/گوگل‌پلی |
| فریم‌ورک | Flutter + Material 3 + Riverpod |
| حس‌وحال | گرم، نرم، شاد و آرام؛ پالت آبی آسمانی/فیروزه‌ای/بنفش ملایم/مرجانی/طلایی |
| حساب کاربری | فعلاً ندارد؛ برای کاهش دادهٔ کودک و پیچیدگی امنیتی |
| مونتایزیشن | فعلاً ندارد؛ بنابراین Poolakey و paywall عمداً اضافه نشده‌اند |
| دادهٔ محتوا | کاتالوگ محلی قابل جایگزینی با API/CMS |

فایل Master Prompt به‌دلیل خالی بودن بخش «اطلاعات پروژه»، با توجه به `README` و کد قبلی پروژه تطبیق داده شده است. پرداخت واقعی، ورود و cloud sync تا وقتی نیاز محصول مشخص نشده‌اند پیاده‌سازی نشده‌اند. یک صفحهٔ وضعیتِ فقط-والد برای ثبت پیش‌نیازهای خرید وجود دارد؛ این صفحه paywall یا خرید آزمایشی نیست.

## لایه‌ها و وابستگی‌ها

```text
Presentation (pages/widgets)
         ↓ Riverpod providers
Domain (CartoonRepository contract)
         ↓
Data (LocalCartoonRepository + models)
         ↓
Core (AppPreferences, theme, utilities)
```

- صفحه‌ها مستقیماً به `SharedPreferences` یا منبع کاتالوگ متصل نیستند.
- `AppPreferences` wrapper واحد داده‌های نمایشی و تنظیمات محلی است؛ رمز، token یا کلید در آن نگه‌داری نمی‌شود و SharedPreferences رمزگذاری‌شده نیست.
- `cartoonRepositoryProvider` محل composition برای تغییر از منبع محلی به REST/GraphQL/Firebase است.
- اطلاعات ویدئو در `EpisodeModel` است؛ پخش‌کننده فقط یک URL HTTPS می‌گیرد.

## چرا این انتخاب‌ها؟

### Riverpod
از قبل Riverpod در پروژه بوده و برای stateهای کوچک، قابل‌آزمون و مستقل از Widget مناسب است. stateهای persistence شامل علاقه‌مندی‌ها، تم، نام والد، autoplay و history هستند.

### SharedPreferences به‌جای Database
نسخهٔ فعلی فقط چند شناسه و درصد پیشرفت ذخیره می‌کند؛ SQLite/Hive در این مرحله پیچیدگی غیرضروری بود. با بزرگ‌شدن آفلاین‌کاتالوگ یا downloadها، migration به database لایهٔ data انجام می‌شود، بدون تغییر UI.

### تصویرسازی برداری به‌جای تصویر تصادفی شبکه
تصاویر تصادفی برای اپ کودک قابل‌کنترل نیستند، روی اینترنت ضعیف تجربه را خراب می‌کنند و ممکن است از نظر حقوقی/کیفی مناسب نباشند. `CartoonArtwork` یک artwork سبک، responsive و بدون asset شبکه است. برای انتشار تجاری می‌توان آن را با assetهای دارای مجوز یا URLهای CDN جایگزین کرد.

### ورود و پرداخت در نسخهٔ فعلی

برای مخاطب کودک، جمع‌آوری حساب و داده باید حداقلی باشد. ورود، analytics اختصاصی و SDK پرداخت اضافه نشده‌اند. صفحهٔ «وضعیت خرید» پشت Parental Gate فقط غیرفعال‌بودن خرید و پیش‌نیازهای باقی‌مانده را نشان می‌دهد؛ قیمت، SKU، entitlement یا دکمهٔ خرید ندارد. خرید واقعی فقط پس از تعیین فروشگاه، محصول/قیمت، SDK سازگار، اعتبارسنجی رسید، بازیابی و مزایای دارای مجوز می‌تواند در feature جدا پیاده‌سازی شود.

## Design System (v1.2)

- **Primary:** `#2E9BEB` (آبی آسمانی) — پایهٔ برند
- **Secondary:** `#17BFA8` (فیروزه‌ای) — حس اعتماد و تازگی
- **Accentها:** مرجانی `#FF7A59`، بنفش ملایم `#8F7AED`، زرد طلایی `#FFC53D`، صورتی — فقط برای سلسله‌مراتب، دسته‌ها و بازخورد
- **Typography:** Vazirmatn 33.003 (OFL 1.1) خانوادهٔ اصلی متن است؛ ۴ وزن 400/500/700/900 باندل شده و `google_fonts` وجود ندارد. `VazirmatnRoundDots` فقط برای display/headline/titleLarge استفاده می‌شود؛ دو وزن 700/900 از گونهٔ رسمی Round-Dots همین پروژه، با نقطه‌های گردتر، glyph map و advance width همسان در دو وزن بررسی‌شده (چند side-bearing جزئی متفاوت است). ارقام contextهای عددی با `toFaDigits()` فارسی می‌شوند.
- **مقایسهٔ فونت:** Estedad رسمی نیز OFL 1.1 دارد، ۹ وزن و محور متغیر `wght` از 100 تا 900 ارائه می‌کند و README آن را نرم، فشرده و screen-oriented توصیف می‌کند؛ glyphهای نمونهٔ فارسی، ارقام فارسی/عربی/لاتین و علائم رایج در آن بررسی شدند. برای بدنه انتخاب نشد تا Vazirmatn جاافتاده حفظ شود؛ به‌جای افزودن خانوادهٔ نامرتبط، نسخهٔ گردنقطهٔ Vazirmatn تنها مکمل تیتر است. خوانایی/line-wrap نهایی باید با Flutter و دستگاه نیز بررسی شود. منابع: [Vazirmatn](https://github.com/rastikerdar/vazirmatn) و [Estedad](https://github.com/aminabedi68/Estedad)، هر دو OFL 1.1.
- **Radius:** 12 / 18 / 24 / 32 / 42 — **Spacing:** 4 / 8 / 16 / 24 / 32، حاشیهٔ صفحه `AppTheme.pageMargin`
- **Shadow:** soft/medium بر پایهٔ brightness + `AppTheme.glow(color)` برای دکمه‌های CTA
- **Motion:** `AppMotion` منبع مشترک duration/curve است (micro ۱۵۰ms تا entrance ۵۲۰ms، curve امضای `Cubic(.22,1,.36,1)`). `MotionScope` + `context.motion` حرکت را با ترجیح سیستم/والد کاهش می‌دهد؛ loop و shimmer خاموش، نشانگر انتظار ثابت و route بدون جابه‌جایی می‌شود. ورود تدریجی scale بسیار ظریف دارد، carousel پارالاکس محدود و mascot در نقاط منتخب به لمس با bounce کوتاه/بازخورد لمسی واکنش نشان می‌دهد.
- **عمق بصری و مرز سه‌بعدی:** poster و mascot با `CustomPainter` و path/gradient/نور لبه‌ای/سایه، تصویرسازی دوبعدیِ شبه‌سه‌بعدی‌اند. کارت‌ها elevation کم و border مشترک دارند. در پروژه مدل 3D قابل‌چرخش، asset رندرشدهٔ سه‌بعدی یا موتور سه‌بعدی وجود ندارد؛ افکت‌های فعلی را سه‌بعدی واقعی نمی‌نامیم. هیچ تصویر bitmap یا مجوز جدیدی اضافه نشده است.
- **Dark mode:** از `ThemeMode` و ColorScheme واقعی؛ سطح‌های navy، border روشن ملایم و elevation کم برای عمق کنترل‌شده

## مرز آماده‌سازی درآمدزایی (بدون فعال‌سازی پرداخت)

- هیچ SDK پرداخت، درگاه، شناسهٔ محصول، قیمت یا entitlement اضافه نشده است. صفحهٔ «وضعیت خرید» تنها یک نقطهٔ اتصالِ والد-محور و پشت Parental Gate است؛ خرید غیرفعال را صریح می‌گوید و فقط پیش‌نیازها را فهرست می‌کند، نه paywall یا تراکنش آزمایشی.
- مالک محصول باید فروشگاه مقصد (کافه‌بازار/مایکت/سایر)، محصولات و قیمت‌های واقعی، مزایای قابل‌فروش و حقوق محتوا را مشخص کند.
- پیش از فعال‌سازی، نسخهٔ SDK باید با Flutter/Android پروژه سازگار باشد؛ اعتبارسنجی رسید، لغو، خطا و restore باید طراحی و روی محیط آزمون فروشگاه تأیید شوند. وضعیت خرید با مقدار محلی SharedPreferences معتبر نمی‌شود.
- `CartoonModel` و `CartoonRepository` ورودی محتوا هستند؛ entitlement آینده باید در لایهٔ domain/data و با تأیید قابل‌اعتماد پیاده شود. Parental Gate صرفاً کاهش‌دهندهٔ دسترسی اتفاقی است و مرز امنیتیِ محکم نیست.


## امنیت و حریم خصوصی

1. keystore و `key.properties` از Git خارج‌اند؛ manifest فعلی `allowBackup=false` دارد.
2. اپ برای کاتالوگ فعلی به `INTERNET` نیاز دارد؛ Storage permission درخواست نمی‌شود.
3. نام‌های نمایشی، آواتار، تنظیمات، علاقه‌مندی‌ها و progress پخش native در `SharedPreferences` محلی می‌مانند؛ cloud sync و analytics اختصاصی نداریم.
4. پخش embed از Aparat است؛ میزبان ثالث ممکن است کوکی، دادهٔ فنی شبکه یا تبلیغات خود را پردازش/نمایش دهد. رابط کارتونیا نباید ادعای «بی‌تبلیغ» یا «بدون ردیابی» کند.
5. پرسش والدین برای کاهش ورود اتفاقی است؛ به‌تنهایی احراز هویت، کنترل والدین سیستمی یا حفاظت از خرید محسوب نمی‌شود.
6. URLهای محتوای بیرونی باید HTTPS باشند. هنگام اتصال API، token فقط در secure storage نگه‌داری شود، نه SharedPreferences.
7. پیام خطای player جزئیات فنی یا URL را به کاربر نمایش نمی‌دهد.


## مرزهای فعلی نسخهٔ ۱.۲.۱+4

- کاتالوگ فعلی ۱۶ embed آپارات دارد؛ لینک عمومی به‌معنی مجوز استفاده یا تأیید محتوایی نیست. بازبینی حقوقی/محتوایی هنوز لازم است.
- backend، دانلود آفلاین، notification، پرداخت و analytics هنوز در Scope تأییدشده نیستند.
- CI موجود در `.github/workflows/apkmaker.yml`، Flutter 3.19.6 را pin می‌کند و `pub get`، تست‌ها و APK release را اجرا می‌کند؛ تحلیل ایستا و آزمون دستگاه باید جداگانه نیز تأیید شوند.
